# APM Task Coverage

## Operational Contract

- The authoring checkout (`~/src/github.com/jey3dayo/apm-workspace`; "the checkout" below) is the day-to-day source of truth for APM catalog content, task wiring, and supporting docs. On the native HOME, `~/.apm` holds only the APM consumer state.
- The real HOME is native. The normal rollout is `mise run native:sync` (or `mise run native:sync -- --https` without SSH); its steps and rollback are in section B of `docs/native-distribution.md`. `native:migrate`, `native:migrate-rollback`, `native:reinstate`, `native:opencode`, and `setup:mcp:host` also write to HOME. The legacy writer (`apply`, `deploy`, `upgrade`, `refresh` and their helpers) was removed on 2026-11-10; its last version is commit `0bcce09`.
- `~/.config` is reference-only for this workflow. It is not the operational source of truth.
- The bold-heading formatter helper (`replace-bold-headings.ts`) is vendored into this repository at `scripts/replace-bold-headings.ts`; there is no operational exception under `~/.config` for it.
- The global guide is the catalog instruction `catalog/.apm/instructions/ai-collaboration.instructions.md`. `native:apply` and `native:migrate` run `apm compile -g --clean`, which writes `~/.codex/AGENTS.md` and `~/.cursor/AGENTS.md` and never overwrites a root without the APM marker; Claude reads the guide as the native rule a user-scope install adds.
- Codex skills deploy separately to `~/.agents/skills`; skill rollout verification must inspect the deployed `SKILL.md` there.

## Source Of Truth

Path-by-path ownership (catalog, optional-skills, workspace-only skills, lockfiles, caches) is owned by the Ownership table in the root `AGENTS.md`. This file covers only task responsibilities.

## Task Visibility

`mise tasks` lists only the entry points. Parts that exist to be composed by an aggregate, or to be reached only during recovery, carry `hide = true` and stay directly runnable by name:

- check parts of `check` / `format:check`: `format:markdown`, `format:markdown:check`, `format:markdown:bold-headings`, `format:markdown:bold-headings:check`, `format:toml`, `format:toml:check`, `format:yaml`, `format:yaml:check`, `lint:yaml`, `lint:actions`, `actions-lock:verify`, `lint:frontmatter`, `lint:catalog-leaks`, `validate:workspace`, `validate:catalog`
- `format:check`, `validate`, and `test:sh` are aggregate parts but remain visible because CI or the procedures call them directly; `test:sh` is also a pre-push job.
- recovery-only: `agmsg:state:save`, `agmsg:state:restore` (`native:rehearse` and `native:migrate` save and restore the roster themselves; these tasks recover a roster unlinked outside of them)
- bootstrap hooks: `bootstrap`, `setup:mcp:host`
