# catalog

This directory contains the managed catalog for the global APM workspace.

- Edit personal skills in `catalog/.apm/skills/<id>/`
- Keep repository-specific or infrequently used skills in
  `optional-skills/<id>/` instead of this global catalog, and install
  each skill by its direct repository ref.
- Edit shared guidance in `catalog/.apm/instructions/ai-collaboration.instructions.md` (the global guide; its body below the frontmatter is what every tool reads), `commands/**`, and `rules/**`. `catalog/AGENTS.md` is gone, and `validate:catalog` stops if it comes back
- The guide reaches each tool through APM: a user-scope install adds it as the Claude rule `~/.claude/rules/ai-collaboration.md`, and `mise run apply` runs `apm compile -g --clean` to write `~/.codex/AGENTS.md` and `~/.cursor/AGENTS.md`. APM never overwrites a root without its marker, so apply leaves an existing root alone. A root that carries the marker and still matches its Build ID is APM output: compile rewrites it, and `--clean` removes an unedited Claude root once the rule covers it. If a Codex or Cursor root (or the file it links to) was edited after compile, apply skips the compile and warns instead of overwriting it. APM itself keeps an edited `~/.claude/CLAUDE.md`, so the install guard refuses one, as well as a symlink to a compile output and a copy whose marker line was deleted, because each would sit next to the rule. To keep your own edits, remove the marker line, and APM then treats the file as hand-written; in `~/.claude/CLAUDE.md` also remove the guide, which the rule provides. `apply` also copies the body to `~/AGENTS.md` (Pi) and to `~/.config/opencode/AGENTS.md` (OpenCode would otherwise fall back to `~/.claude/CLAUDE.md`), the latter only while that file is a copy of the guide, or is absent and `~/.claude/CLAUDE.md` (OpenCode's fallback) is absent, a legacy copy or unedited APM output
- A root the old sync copied (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.cursor/AGENTS.md` byte-equal to a committed `catalog/AGENTS.md`) is moved only by `mise run migrate:roots`: it previews by default, and `mise run migrate:roots -- --apply` renames each copy to `<name>.<UTC time>.bak`. Hand-written roots, symlinks and APM output are left alone. Until `~/.claude/CLAUDE.md` is moved, `install:catalog`, `refresh`, `install:pins` and `upgrade` refuse to run, since APM would add the same guide as a Claude rule and Claude would load it twice. They also refuse an edited or older copy that still opens with the guide's title; migrate:roots does not move such a file, so move it aside by hand. A bare `apm install -g` typed outside these tasks is not checked. Afterwards run `mise run install:catalog` and `mise run deploy`. To roll back, move each `.bak` back over its root, and move `~/.claude/rules/ai-collaboration.md` aside if install:catalog already added it
- Edit agents in `catalog/.apm/agents/<name>.agent.md`; `mise run apply` renders them with APM in a temporary project and places them atomically in `~/.claude/agents/<name>.md` and `~/.cursor/agents/<name>.md`, overwriting a differing regular file and leaving other files alone (Codex and OpenCode receive none). A symlink there (for example into dotfiles) is kept when its content already matches; when it differs, apply stops before placing anything instead of cutting the link
- `skills` are authored under `catalog/.apm/skills/**` and staged into the published package at the same path; do not recreate a top-level `catalog/skills/`
- `catalog/.apm/` holds only `skills/`, `agents/` and `instructions/ai-collaboration.instructions.md`, and only what `prepare:catalog` rebuilds: regular files inside a skill directory (one holding `SKILL.md`), agents named `agents/<name>.agent.md` directly under `agents/`, and that one instruction. `validate:catalog` and `prepare:catalog` stop on anything else there (another primitive, a file outside a skill, another agent name, a symlink or special file, or an entry they cannot read)
- `commands/**` stays top-level because it is runtime-synced shared guidance, not nested skill package content
- Edit this directory directly, then run `mise run prepare:catalog` before commit/push
- Install ref: `jey3dayo/apm-workspace/catalog#main`
- `catalog/apm.yml` sets `targets: [claude, cursor, agent-skills]` so Codex receives no agents. A consumer that targets only `codex` therefore gets nothing from this package, not even skills (APM 0.35.0 fails `apm install <ref> --target codex`); include `agent-skills` in its targets (for example `--target codex,agent-skills`) to receive the skills under `.agents/skills`
