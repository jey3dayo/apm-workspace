# Hook Selection

上から順に当てはめ、最初に合ったものを使う。表の上 3 行は「state を作らない」選択肢で、ここで済むなら hook は要らない。

## state を作らない

| 手段             | 使う場面                                                                   | 使わない場面                                                        |
| ---------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| レンダー中に計算 | props / state / context から決まる値（絞り込み結果、合計、表示用の整形）   | 計算結果をユーザーが編集する（初期値として state に入れる）         |
| `key`            | 対象（ユーザー ID、記事 ID など）が変わったら子の state を全部捨てたい     | 一部の state だけ残したい（ID を持ってレンダー中に導出する）        |
| URL              | 検索語・タブ・ページ番号など、共有・リロード・戻る操作で復元したい UI 状態 | 入力途中の値や hover など、一瞬で変わり復元しても意味のない一時状態 |

## hook を使う

| hook                   | 使う場面                                                                                         | 使わない場面                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `useState`             | 画面に出る、ユーザー操作で変わる独立した値                                                       | 他の state から計算できる値。表示に使わない値（→ `useRef`）                                            |
| `useReducer`           | 複数の値が 1 つの操作でまとめて変わる。更新規則を純粋関数に切り出してテストしたい                | 独立した値が 1〜2 個だけ。副作用を含む更新（→ `useActionState`）                                       |
| `useTransition`        | 自分で起こす更新を低優先にしたい、Action の pending を出したい（タブ切替、Action の実行）        | 制御された input の値の更新（入力が遅れる）。値を受け取る側で遅らせたい（→ `useDeferredValue`）        |
| `useDeferredValue`     | 受け取った値で重い描画をする部分だけ遅らせたい。古い結果を出したまま新しい結果を準備したい       | ネットワーク要求の回数を減らしたい（デバウンスやキャッシュの仕事）。描画が軽い                         |
| `useOptimistic`        | Action の完了前に結果を先に見せたい（いいね、追加、並べ替え）。失敗時は元に戻ってよい            | Action の外での更新。失敗時に戻ると困る操作（決済など、確定前に成功表示してはいけないもの）            |
| `useActionState`       | 送信の結果・エラー・pending を 1 か所で持つ。前回の結果を次の送信で使う                          | 送信を並列に走らせたい（呼び出しは順に処理される → `useState` + `useTransition`）。純粋な UI 状態      |
| `useFormStatus`        | 送信ボタンなど `<form>` の子コンポーネントが、親フォームの pending や送信中データを知りたい      | フォームを描画しているのと同じコンポーネントから使う（親の `<form>` しか見えない）                     |
| `useSyncExternalStore` | React の外にある値の購読（ブラウザ API、外部ストア）。`getSnapshot` は変化がなければ同じ値を返す | React の state で持てる値。`getSnapshot` が毎回新しいオブジェクトを返す実装（無限再描画になる）        |
| `useRef`               | DOM ノード、タイマー ID、表示に使わない値の保持                                                  | レンダー中に `ref.current` を読む・書く（`refs` 規則違反）。依存配列から値を外すための退避先として使う |
| `use`                  | キャッシュされた Promise や context をレンダー中に読む。条件分岐の中でも呼べる                   | Client Component のレンダー中に作った Promise を渡す（毎回作り直されて fallback が繰り返し出る）       |
| `useEffect`            | 外部システムとの同期（接続、購読、非 React ウィジェット、表示されたことによる計測）              | それ以外すべて。[effect-checklist.md](effect-checklist.md) を通ってから使う                            |
| `useEffectEvent`       | Effect の中から最新の props / state を読みたいが、その値の変化で Effect を再実行したくない       | イベントハンドラや子へ渡すコールバック（普通の関数でよい）。依存配列の警告を消すため                   |

## 補足

- `useRef` に「最新の値」を入れて Effect から読むパターンは、React 19.2 以降なら `useEffectEvent` を先に検討する。ref に書くならレンダー中ではなく Effect かイベントハンドラの中で書く
- `useEffectEvent` が返す関数は依存配列に入れず、identity が安定している前提でも扱わない。呼んでよいのは Effect と他の Effect Event の中だけ
- `useDeferredValue` と固定ミリ秒のデバウンスの違い: 前者は端末の速さに合わせて遅れ、途中で新しい入力が来れば描画を捨てる。後者は単に描画を後ろへずらすだけ。描画が重いなら前者、要求の回数を減らしたいなら後者
