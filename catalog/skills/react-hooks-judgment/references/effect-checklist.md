# Effect Checklist

`useEffect` / `useLayoutEffect` を書く前、またはレビューで見つけたときに上から順に確認する。
1 つでも当てはまれば Effect を消して、右の置き換えに移す。

## 置き換えられる Effect

| #   | 兆候                                                                    | 置き換え                                                                                      |
| --- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 1   | props / state から別の state を作って `setState` している               | レンダー中に計算する。重い計算は Compiler に任せるか `useMemo`                                |
| 2   | prop の変化を見て state を全部初期値に戻している                        | 親から `key` を渡して子を作り直す                                                             |
| 3   | prop の変化を見て state の一部だけ直している                            | ID などの元データだけ持ち、残りはレンダー中に導出する                                         |
| 4   | 「ユーザーが○○したから」起きる処理（通知、POST、遷移）                  | その操作のイベントハンドラに移す。複数のハンドラで共有するなら関数に切り出す                  |
| 5   | state の変化を見て親のコールバックを呼んでいる                          | 同じイベントハンドラの中で自分の更新と親への通知を両方行う。または state を親に持ち上げる     |
| 6   | 子が取得したデータを Effect で親に渡している                            | 親で取得して props で渡す。データは上から下へ流す                                             |
| 7   | Effect が state を更新し、それを見て別の Effect がまた更新              | 導出できる値はレンダー中に計算し、次の状態はイベントハンドラの中でまとめて決める              |
| 8   | アプリ起動時に 1 回だけの初期化を `[]` の Effect でしている             | モジュールのトップレベル、エントリポイント、または一度きりのフラグで守る                      |
| 9   | 外部ストアやブラウザ API を購読して `setState` している                 | `useSyncExternalStore`                                                                        |
| 10  | `fetch` して結果を `setState` しているが cleanup がない                 | framework の取得機構かキャッシュ済み Promise + `use` に移す。残すなら下の「fetch を残す場合」 |
| 11  | 依存配列を `[]` にするために値を ref や `useEffectEvent` に逃がしている | 依存が増えて困る理由（オブジェクトを毎回作っている等）を直す。隠さない                        |

判断の目安: その処理は「コンポーネントが画面に表示されたこと」が原因か、「ユーザーが操作したこと」が原因か。前者だけが Effect の仕事で、後者はイベントハンドラの仕事。

## 残してよい Effect

- WebSocket やサードパーティ SDK への接続と切断
- `addEventListener` や `IntersectionObserver` など、React の外の購読
- 非 React のウィジェット（地図、チャート）への値の受け渡し
- 表示されたことが原因の計測（ページビューなど）
- 互いに依存するネットワーク同期（選択肢を順に取得するドロップダウンなど）

残す Effect には、同期している外部システムを 1 行のコメントで書く。書けないならその Effect はおそらく要らない。

```tsx
// 外部システム: チャットサーバーへの接続。roomId が変わったら繋ぎ直す
useEffect(() => {
  const connection = createConnection(roomId);
  connection.connect();
  return () => connection.disconnect();
}, [roomId]);
```

## fetch を残す場合

React 18 以前で Suspense が使えないなど、Effect で取得するしかない場合の最低条件。

- cleanup を必ず書く。`AbortController` で要求を止めるか、無視フラグで古い応答を捨てる（競合状態の対策）
- loading / 成功 / 失敗を 1 つの判別共用体の state で持つ
- 「マウントしたら 1 回」ではなく「state が loading のときに取得する」と捉え直すと、依存配列を `[]` にせずに済み、再取得も state を loading に戻すだけになる（uhyo の記事の考え方）
- キャッシュ、重複排除、再検証が要るなら自前で書かずに取得ライブラリか framework に任せる

## lint との対応

- `set-state-in-effect`: #1〜#3、#7、#9 の多くがここで見つかる
- `exhaustive-deps`: #11 を無効化コメントで黙らせない
- `refs`: レンダー中の `ref.current` 読み書き。#11 の ref 退避で出やすい
