# Pre-install Checklist

Consumer-side repository prerequisites to check before running `apm install` for the first time. These were found by running `apm install` in a consumer repository and observing what broke, not derived from documentation.

| #   | Item                                                                                                                                           | Durability                                                                                                                                                                         | Evidence                                                                                                                                                                                                   |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Add `apm_modules/` and `.agents/` to `.gitignore`.                                                                                             | Permanent: these are install output directories regardless of any lockfile format change.                                                                                          | Install target directories are generated fresh on every `apm install`.                                                                                                                                     |
| 2   | Add `.claude/skills/` to `.gitignore`, and also to the repository's markdown lint and Prettier ignore lists.                                   | Permanent: `.claude/skills/` is another install target directory, independent of any lockfile format change.                                                                       | Omitting the lint/format excludes produced 6 markdownlint MD032 failures under `.claude/skills/`, which failed the pre-push gate.                                                                          |
| 3   | Exclude `apm.lock.yaml` from the repository's YAML lint and formatter. `~/.apm` itself lists it in both `.yamllint.yml` and `.prettierignore`. | Contingent on the repository's lint configuration: it only bites when a rule such as yamllint's `indent-sequences: true` disagrees with the lockfile's block-sequence indentation. | The lockfile is serialized by `apm-cli` through PyYAML `safe_dump`, whose block sequences sit at the parent key's indent. Neither `apm lock --help` nor `apm config list` exposes an output-format option. |

## Why items 1-2 differ from item 3

Items 1 and 2 are about directories `apm install` always creates as install targets; they hold regardless of how the lockfile itself is formatted. Item 3 depends on the consuming repository's lint configuration — a repository with no YAML linter, or one whose rules already accept the lockfile's shape, needs nothing.

Treat the lockfile as accepted-upstream state rather than something to reformat. Inline `# yamllint disable` comments do not survive, because `apm lock` and `apm install` regenerate the whole file.
