# Memory Audit

メモリは観測した時点の記録であり、現状ではない。棚卸しは「この主張はいまも真か」を一次情報で確かめて残す・直す・消すを決める作業で、ファイルの並べ替えではない。

## 手順

1. lint を走らせる: `<このスキルのディレクトリ>/scripts/lint-memory.sh <memory-dir>`。スクリプトはこの SKILL.md と同じディレクトリの `scripts/` にあり、作業中のリポジトリには無いので、絶対パスで呼ぶ（Claude Code なら `"${CLAUDE_SKILL_DIR}/scripts/lint-memory.sh"`）。memory-dir はシステムプロンプトの Memory 節に書かれた絶対パス。終了コードが 0 になるまで、指摘を直す。lint は構造（frontmatter と索引）だけを見る。中身が古いかどうかは手順 2 で確かめる。まだ書かれていないメモリへの `[[link]]` は `note:` として表示されるだけで、失敗ではない（書く価値がある印として許される）。各 note は手順 2 で、書く価値があるなら書き、残骸ならリンクを消す。
2. 主張ごとに一次情報へ当てる。新しい順ではなく、日付の古いものと、コードや設定の挙動を述べるものから見る。当てる先は3つ。
   - repo の docs・skill・`AGENTS.md` が同じことを記録しているか。記録済みなら、メモリは指し先だけにするか削除する（残すのは repo から読めない理由・経緯・運用の癖）。
   - コード・設定・issue / PR の状態。`gh issue view` や `git log -S` のように、現物から取れる事実は現物で確かめる。
   - どちらでも確かめられない主張は、日付つきで「未検証」と書いて残す。
     完了条件: 全メモリに keep / rewrite / delete / pointer のいずれかが付き、各判断に確かめた一次情報（ファイルと行、コマンド、issue 番号）が1つずつ対応している。
3. 書き直す。時系列の追記は、現状を先頭に置いて圧縮する。圧縮で落とさないのは例外で、「全フロア」「すべて」のような全称の主張には、全称を述べている根拠が要る。手順 2 で読んだ資料に反例（「〜だけは残る」）があれば、その反例を結論に含める。
   完了条件: 書き直した各主張が、このセッションで読んだ一次情報に対応している。対応が無い主張は「未検証（日付）」と書く。
4. `MEMORY.md` を直す。1メモリ1行で、descriptions と食い違わせない。lint をもう一度走らせて終了コード 0 を確かめる。
5. 報告する。削除・書き直し・残したものを、確かめた根拠と対にして示す。未検証のまま残した主張は一覧にして添える。

## 他のメモリ操作との境界

- 新しいメモリを書くとき、既存のメモリの追記・更新で済むかを先に見る。
- 他セッションが同じディレクトリを編集していることがある。ディスク上の変更は意図的とみなし、読み直してから触る。
