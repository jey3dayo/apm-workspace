# Rule Propagation

ルールは1か所で決めても、効く場所は複数に散っている。1か所だけ直すと、古いルールで動く読み手（別の bot、別の AI、未来の自分）が残る。本スキルは「決まった変更を、効いている全サーフェスへ、正本ごとに正しい経路で届ける」ための手順と台帳を持つ。何を不整合とみなすかの判断はその場で行い、ここには固定しない。

## 進め方

1. 変更を1文で固定する（旧ルール → 新ルール）。曖昧なら人間に確認してから動く。
2. 効いている場所を洗い出す。下の台帳を起点に、各正本を全文検索する。ローカルにある写しで代用しない（写しは正本より古いことがある。実例: Drive の T3 文書は Muse のローカル写しより進んでいた）。
3. 各サーフェスを実物で読み、古い記述の有無を判定する。無い場所は「変更不要」と記録する。探しに行って無かったことも結果である。
4. サーフェスごとの経路で更新する（台帳の「更新経路」）。他者の担当領域は直接触らず、依頼や note で回す。
5. 並行作業を疑う。更新の直前に最新を取り直す（PR のマージ状態、リモートの新しいコミット、Drive の更新時刻）。マージ済みの PR ブランチへの追加 push は main に入らず取り残される。
6. 報告する。変えた場所、変更不要だった場所、他者待ちの残件を分ける。あわせて経緯を `sources` に記録する（台帳の Drive 行）。

## 主題ごとの効き先

台帳のサーフェスを、主題ごとに具体的なファイルへ落としたもの。新しい主題で伝播したら、ここへ1行足す。

- T3 運用: apm の `t3-stack` / `orchestrator-worker`（envelope と tier 表）、Muse の T3 コネクタ doc と委譲スキル、Drive howto の `t3-mcp-connect.md` / `t3-mcp-for-bots.md` / `t3-runtime-modes.md`（2026-11-17 に整合済み）

## やらないこと

- 写しだけ直して正本を放置しない。
- 他者の担当文書を、断りなく書き換えない。共有文書のルール行のように担当が跨る場合は、更新した事実を note で必ず周知する。
- 秘密の値を伝播先に書かない。書くのは置き場所まで。
- 伝播のついでに、頼まれていないルール変更を混ぜない。気づいた不整合は報告に分けて出す。
