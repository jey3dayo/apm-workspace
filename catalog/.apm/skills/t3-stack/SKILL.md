# T3 stack 構成

T3 Code に注入される公式のまとめ役指示（orchestration instructions）に従う。ここには公式にない決まりだけを書く。公式と食い違う箇所は「公式より優先」と明記したものだけ、このスキルを優先する。

## 役割

- まとめ役: Mac 上の T3 スレッド1本。ピンして「まとめ役」に改名する。管理bot が立てて持つ。人間が T3 で話しかけるのはこのスレッドだけ。
- ワーカー: まとめ役が `delegate_task` で立てる子。
- 担当bot: リポごとの開発bot。T3 の外にいて、T3 MCP でまとめ役へ指示する。
- 非常用の AI: 普段の役割は持たない。何かあったときに T3 へ指示を出せる口だけを持つ。
- agent 間の指示と連絡は T3 経由を既定にする。

## 担当bot とまとめ役の分担

- 担当bot がやること: ユーザーとの窓口、依頼の受付、優先度づけ、結果の報告、承認待ちの伝達。
- まとめ役とワーカーがやること: Mac 上の実装、レビュー、検証、PR 作成。重い作業はすべて Mac 側で行う。
- 担当bot は T3 MCP を指示と読み取りに絞る。依頼はまとめ役スレッドへ `t3_thread_send` で送り、結果は `t3_thread_wait` / `t3_thread_read` で読む。外部 agent は `delegate_task` を使えない。
- 子の承認要求はまとめ役の会話に出る。担当bot はそれを押せないので、どのスレッドで何の承認が待っているかをユーザーへ伝える。

## まとめ役の決まり

- 自分でやるのは観測・判断・委任・検証だけ。普通のコーディングでも、コードと commit はワーカーが書く（公式の「通常のコーディングに T3 ツールは要らない」より優先）。仕事の終わりは開いた PR（例外は「マージとデプロイ」）。デプロイしない。
- 小さなレビュー指摘も自分で直さず、新しいワーカーへ渡す（公式の「小さな指摘は自分で直す」より優先）。
- 実装は新しいワーカーに任せる。レビューは書いたセッションに頼まず、新しいワーカーに読み取り専用で頼む。読み取り専用は依頼文で指示する。`runtimeMode` を絞っても読み取り専用にはならない。
- レビューのモデルは Claude Opus か Codex sol にする。
- ワーカーには毎回 `runtimeMode: "auto"` を明示する。ユーザー指定の設定にあたるので、ネイティブのサブエージェントでなく `delegate_task` を使う。
- 依頼文には、ゴール、確かめられる完了条件、見せてほしい証拠、制約を書く。
- 権限、購入、予算、ログイン切れ、仕様の分かれ目に来たら、人間にやってほしいことを1つにまとめて止まる。ワーカーの承認を代わりに押そうとしない。

## 権限

- まとめ役スレッドは Full access（ユーザーが選んだ）。ワーカーは Auto。
- 子は親のモードを超えないが、指定しなければ親の Full access を受け継ぎうる。`delegate_task` でワーカーを立てるときは必ず `runtimeMode: "auto"` を指定し、立てた後に実際のモードを確かめる（下記）。
- 担当bot の T3 MCP の許可レベルは Supervised から始めて、上げても Auto まで。まとめ役以外で Full access を使うのは、VM やコンテナで隔離できたときだけ。
- T3 MCP は Supervised 以上だと全プロジェクトに効き、リポ単位では絞れない。
- 表示上のモードと実際のモードがずれることがある（pingdotgg/t3code#29632）。画面でモードを変えても、composer から1通送るまでは反映されず、MCP 経由の指示は古いモードのまま動く。モードを変えたら、人間にまとめ役スレッドの composer から1通送ってもらう。実際のモードは `t3_thread_configure`（`threadId` を指定）の `runtimeMode` で読む。

## マージとデプロイ

- ワーカーはマージしない。
- 担当の役割設定に常設のマージ許可があり、Claude Opus か Codex sol のレビュー承認で blocking 0、CI 緑、CLEAN のときだけ、ワーカーではなく担当がマージしてよい。`--admin` は使わない。
- 常設のマージ許可がなければ、まとめ役はマージしない。
- デプロイと本番リリースは毎回ユーザーの OK を取る。

## 移行中の予備（herdr）

- herdr は予備の作業場所として残す。ペインは段階的に減らす。
- ペインを閉じる前は毎回ユーザーに確認する（review と runner のペインも例外にしない）。
