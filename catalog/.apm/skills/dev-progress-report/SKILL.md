# Dev Progress Report

報告の読み手の仕事は判断だけに絞る。本文を読まないと判断できない報告は不合格で、根拠や証拠は本文に混ぜず「詳細」リンクの先へ追い出す。

## 形式

```text
STATUS: <状態> | <決めることを1行>

やったこと
- <最大3行。PR / Issue はリンク、時刻は JST>

待ってること
- <誰の何待ちか。無いときは「なし」1行>

次にやること
- <最大2行。判断が来たら何をするか>

触れていない: <触れていない範囲。触ったときは触った範囲>
詳細: <状況ファイル / Issue へのリンク>
```

## ルール

- STATUS は必ず先頭に置く。状態の語彙は 判断待ち / CI待ち / 作業中 / 完了 / 停止 の5つで固定し、それ以外の状態語を作らない。
- 判断待ちのときは、STATUS 行だけで返事ができる形にする（y/n か番号選択肢）。決めることが無いときは「なし」とし、代わりに現在の待ちや進行を短く書く。
- 待ってることの主語は「あなた」と書かず、宛先の名前で書く。
- 接頭辞（例: [止まった]）は付けない。STATUS と二重になる。流れ図（mermaid）も書かない。流れは STATUS と「次にやること」で足りる。
- 根拠・未確認事項・開示のような証拠類は本文に入れず、「詳細」リンク先へ置く。本文は600字を目安にする。
- 完了で残件が無いときは、STATUS と やったこと 1行だけで終える。待ってること / 次にやること / 触れていない / 詳細 は書かない。
- 本番環境など不可逆な面に触れていないときは、その旨を「触れていない」に明記する。触れたときは触れた範囲を書く。

## 使わない場面

- 短い質問への回答、通常の会話、コードレビューの指摘本文には使わない。
- 読み手に判断が無く、単なる通知で済むものは1文で済ませる。
